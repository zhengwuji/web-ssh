当前能力

把日常服务器工作集中在一个标签页里。

连接、传输文件、整理重复工作，并给每个用户一个独立的安全环境。

01

已保存的连接

保存主机、用户名、认证方式、跳板机与可选的后连接命令，随时用于下一次会话。

  • 跳板机
  • 最近连接
  • 命令集
02

终端工作区

跨标签页与分屏窗格工作，或聚焦单台 Linux 服务器，把它的终端、实时资源状态、文件与笔记放在一起。

03

SFTP 文件管理

在活动终端旁打开 SFTP，或使用完整的双窗格管理器来预览、编辑与执行服务器间传输。

04

多种身份方式

支持使用 bcrypt 密码的本地账号、可选的通行密钥、恢复码，或带 PKCE 的可选 OpenID Connect。

05

内置运维能力

管理用户、审阅结构化审计事件、控制注册开关，并创建或恢复经过校验的备份。

一个工作区

当前服务器始终在视野内。

让一台 Linux 终端、它的 SFTP 文件、实时资源状态与笔记同时可见。任务需要更多主机时，切换到双窗格或四窗格 SSH。

安全源于自主掌控

让访问能力紧贴它所管理的基础设施。

WebSSH 运行在你自己的环境中。账号、连接数据、密钥、审计事件与备份都留在你可控的存储上。

阅读安全文档 ->
01

加密的密钥存储

已存储的 SSH 私钥使用按用户派生的密钥与带认证的加密算法保护。

02

主机信任与隔离

持久化的主机密钥校验、会话归属守卫、CSRF 防护、限流与安全响应头共同守护关键边界。

03

本地化交付

浏览器依赖库均已固定版本并随 WebSSH 一起分发。产品界面不会在运行时加载 CDN，也不发送遥测。

如实说明架构

一个专注的网关，而不是又一个控制面。

WebSSH 负责终结浏览器会话，并向你的目标主机发起 SSH 或 SFTP 连接。实时会话与配额状态是进程内的，因此应用必须以单 worker 运行。

  1. 01浏览器本地托管的界面资源
  2. 02WebSSH认证与会话边界
  3. 03你的主机SSH 与 SFTP 目标

扩展边界：请只运行一个应用 worker。横向扩展的前提是先把实时会话与配额状态外置。

快速开始

一条命令，从镜像到首次登录。

用持久化数据卷运行已发布的容器，然后在 http://localhost:5000 创建第一个管理员。

不要把一个全新且尚未认领的实例暴露给不可信网络。请先完成首次账号初始化再对外发布。

Docker
docker run -d \
  --name webssh \
  -p 5000:5000 \
  -e CORS_ORIGINS=http://localhost:5000 \
  -v webssh_data:/app/data \
  --restart unless-stopped \
  ghcr.io/zhengwuji/web-ssh:latest
