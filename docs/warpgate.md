# Warpgate SSH 连接

该集成**默认处于禁用状态**。管理员必须先启用
**设置 → 管理 → 集成 → Warpgate / SSH 网关**。
此全局设置适用于所有 WebSSH 用户，并保存在现有的
应用设置存储中。更改它需要常规的管理员二次
验证。更改设置后请重新加载已打开的工作区。

禁用会阻止新的网关终端与 Quick SFTP 连接、网关
配置变更，以及未完成的网关身份验证。现有配置会
保留，已建立的会话不会被断开。即使较旧的浏览器标签页
仍显示已启用的 UI，服务器也会强制执行该设置。

启用后，使用一个普通的 WebSSH 配置连接到现有的 Warpgate SSH 端点：

1. 输入网关主机名和 SSH 端口。
2. 在用户名处输入准确的 Warpgate selector，例如 `alice@example.com:production`。
3. 选择 **Password** 或现有的 **SSH 密钥**。使用 Password 时，将密码留空以启动交互式身份验证。
4. 响应额外的身份验证提示。浏览器审批链接仅在点击时打开。审批后返回 WebSSH 并继续。
5. 在临时网关终端中查看任何目标主机密钥或访问审批提示。

不需要额外的服务、Compose 设置、数据库迁移或依赖。普通 SSH、现有跳板主机和 Tailscale 连接保持其原有路径。普通 SSH 跳板主机可以位于网关终端连接之前；Quick SFTP 不增加跳板主机或 Tailscale 支持。

当全局启用时，该集成通过一个经过校验的 `user:target` 用户名进行选择。
普通 SSH 保留其现有的身份验证、取消和 banner 等待
实现；普通 Quick SFTP 保持同步。网关终端与
Quick SFTP 尝试共享它们各自有界的交互生命周期。

## 安全与兼容性边界

- selector 是选择加入一条独立的身份验证路径。它们并不表示某台服务器可信；现有的按用户网关主机密钥检查和网络限制仍然适用。
- 网关控制对其目标的访问。WebSSH 的网络策略检查的是网关端点，而不是隐藏在其后的目标。
- 密码、额外因素和审批响应都是临时性的。它们绝不会存储在配置中。额外因素会被显式作答；原始密码绝不会被复用为 OTP。
- 每次交互都属于单个 WebSSH 用户、socket 和请求。挑战是一次性的，会强制执行截止时间和字节限制，待处理的网关任务共享现有的后台任务配额。
- Warpgate 目标主机密钥检查和审批策略保持启用。不存在自动接受目标主机密钥的行为。
- 终端建立需要一个支持 PTY 的目标以及一个有界的 `printf` exec 探测。只有在 nonce 响应且退出成功之后，WebSSH 才会运行常规终端/tmux 建立或配置的启动命令。
- Quick SFTP 为网关提示使用临时 PTY，并使用单独的 SFTP 通道。目标必须在建立期间允许这两个通道；禁用 PTY 或仅支持单通道的目标不受此路径支持。
- 现有的配置文件认证类型保持不变。较旧的 WebSSH 版本可以读取配置文件文档，但无法使用新的 selector 语法进行连接。
- 不支持 ticket 密钥、`#` selector、自动目标发现、网关管理和非 SSH 协议。

参考实现已针对 Warpgate 0.29.0 和 Paramiko 5.0.0 进行测试。仅网关传输使用 Paramiko 的 `ServiceRequestingTransport`，因此多因素身份验证只会请求一次 SSH 认证服务。其初始服务等待被显式限定界限；升级 Paramiko 时必须重新检查这个小的兼容性覆盖。
